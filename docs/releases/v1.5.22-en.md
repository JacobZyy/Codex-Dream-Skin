# Codex Dream Skin v1.5.22

[中文](https://github.com/JacobZyy/Codex-Dream-Skin/blob/v1.5.22/docs/releases/v1.5.22.md) · **English**

This fork adds optional trusted local `theme.js` scripts, allowing theme authors to manage their decorations, layout and image-loading lifecycle on Codex's native page. Ordinary image/CSS themes keep their existing behavior and need no script or trust grant.

These notes describe the v1.5.22 changes. Check the [fork Releases](https://github.com/JacobZyy/Codex-Dream-Skin/releases) for publication status and available installers.

## New features

- **Scripts bundled with themes**: macOS and Windows can save, switch and restore an optional `theme.js` with a theme. `theme.json` stays at `schemaVersion: 1` and opts in with `"script": "theme.js"`. Official application files remain untouched.
- **Explicit trust by content**: Import only adds a saved theme; it does not execute or trust its script. Review the complete code, use `--trust-theme-script --theme-dir <reviewed-theme-directory>` to grant its exact SHA-256, then select the theme to apply it. The trust command itself does not execute the script. Changed bytes require a new review and grant for the new hash.
- **Switch, reload and restore lifecycle**: A script runs once per generation. A → B → A cleans up the previous generation and runs A again; a page reload remounts the current trusted script. Restore aborts it before running its registered cleanup callbacks. A script can return a promise to await preparation such as image decoding; pending or failed preparation cannot be reported as rendered successfully.

## Fixes and improvements

- **macOS live switching**: Refresh waits for in-flight connections, processes only initialized windows and rechecks their identity after asynchronous work, preventing auxiliary windows from causing repeated failures or stale reload scripts.
- **Existing theme names**: Names containing the script-slot literal still load correctly instead of being mistaken for an unfilled template.

- **Consistent theme contents**: Both platforms include the declared script in theme copying, saved replacement, content fingerprints, watched refresh, snapshots and rollback, preventing missing scripts or stale contents after switching.
- **Package validation**: Scripts must be nonempty UTF-8, at most 6 MiB, and pass syntax parsing and manifest byte-count/SHA-256 checks. Static `--check-payload` parses without executing the script. Existing path, link, archive, image and Safe CSS checks remain in force.

## Upgrading and usage

A script package must register `theme.js` with the `application/javascript` media type, use `skinApiVersion: 2`, declare the `theme-script` capability and set `minClientVersion` to at least `1.5.22`. Local simplified three-file ZIPs cannot carry scripts. See the [trusted theme script documentation](https://github.com/JacobZyy/Codex-Dream-Skin/blob/v1.5.22/docs/theme-scripts.md) for complete trust commands and the API.

Third-party scripts can access Codex's page and chat content. This API is not a sandbox. Authors must register cleanup for all owned nodes, listeners, observers, animations, URLs and native-style changes, and check the abort signal in asynchronous callbacks. The client cannot undo arbitrary unregistered page modifications. Grant trust only to the exact content you have reviewed.

This capability belongs to this fork. The current upstream client and DreamSkin.cc gallery/Studio do not support executable theme packages. Older clients should reject packages requiring Skin API 2 / client 1.5.22. Local implementation and testing do not imply online support or a public release.
